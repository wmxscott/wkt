# wkt picker — implementation plan

**Spec:** `docs/superpowers/specs/2026-10-07-wkt-tui-design.md`
**Branch:** `tui` (one PR)
**Method:** test first, one commit per task. After every task, `bats test`, `zsh -n bin/wkt` and `shellcheck test/*.bats test/*.bash` all pass.

## Ground rules

- All code goes in `bin/wkt`. Match its style: `local` declarations, `print -r --`, `die`/`warn`/`step`, short comments only where the code can't explain itself.
- Nerd-font glyphs are always written as `$'\uXXXX'` escapes.
- Tests never reach a real fzf, Herdr or terminal. `PATH` in tests already leaves out `~/.local/bin`, so only the stub `fzf` can be found.

## Task 0: stub fzf and test helpers

**Files:** `test/test_helper.bash`

1. In `common_setup`, write `$STUB_BIN/fzf` (bash):
   - `--version` prints `${STUB_FZF_VERSION:-0.74.4 (stub)}` and exits 0.
   - Any other call bumps a counter in `$STUB_FZF_DIR/count`, saves its arguments NUL-separated to `$STUB_FZF_DIR/<n>.args` and its stdin to `<n>.in`, then replays `$STUB_FZF_DIR/reply.<n>`. The reply's first line is the exit code and the rest is stdout. A missing reply prints `stub fzf: no reply for call <n>` and exits 98.
   - Export `STUB_FZF_DIR="$TMP/fzf"`, and also `WKT_ASSUME_TTY=1` and `WKT_THEME=dark`.
2. Add `XDG_*` and `WKT_*` to the scrubbed variables. `XDG_*` is already there.
3. Helpers:
   - `fzf_reply <n> <code> [<line>...]` writes one reply.
   - `fzf_args <n>` prints call n's arguments, one per line.
   - `fzf_input <n>` prints call n's stdin.
   - `fzf_calls` prints the call count.
4. The existing test `no arguments prints usage to stderr and exits 2` must still pass. Give it `unset WKT_ASSUME_TTY` so it really runs without a terminal.

**Check:** the whole suite still passes. **Commit:** `Add a stub fzf to the test helper`.

## Task 2: list screen, plain rows, Enter and Esc

Tests:

- `rows: one per worktree, .bare left out`. Use a `.bare` layout plus `wkt new -b topic --no-herdr`, reply `130`. `fzf_input 1` has `main` and `topic`, and no `.bare`.
- `rows: default branch first, cursor on the current worktree`. From `$LAYOUT/topic`, the args contain `load:pos(2)`, or similar.
- `enter: prints the worktree path and nothing else`. Unset `HERDR_TAB_ID`. Reply `0` with lines: query (empty), key (empty), the row. Use `run --separate-stderr`; `$output` is exactly `$LAYOUT/topic`.
- `esc: prints nothing, exit 130`.
- `search matches the branch only`. The args contain `--nth`, `2` and `--with-nth`, `1..3`.

Code:

- At the top of `cmd_ui`: `exec 3>&1 1>&2`. All normal output then goes to stderr, and only the result is written to fd 3. Command substitutions still capture fzf.
- `ui_rows`: parse `git worktree list --porcelain` (`worktree`, `HEAD`, `branch`, `detached`, `bare`, `locked`, `prunable`). Skip bare entries. Put the default branch first. Each row is `head⇥branch⇥tail⇥path`, with no colour yet.
- `ui_fzf <prompt> <header> [args…]` adds the spec's shared settings (§3) and returns fzf's status.
- List call: `--delimiter $'\t' --with-nth 1..3 --nth 2 --tabstop 1 --expect ctrl-n --print-query`, plus `--bind load:pos(N)` when N > 1.
- Read the output as three lines: query, key, selection. The path is field 4 of the selection. Exit 130 passes through. Exit 1 means no match, which Task 6 handles.
- Result: `print -r -- "$path" >&3`.

**Commit:** `List worktrees in the picker and print the chosen path`.

## Task 3: theme, colours, icons, header

Tests (all on `fzf_input 1` or `fzf_args 1`):

- `dark theme: Macchiato colours`: contains `38;2;202;211;245`, which is Macchiato `text`.
- `light from the theme-monitor trigger file`. Unset `WKT_THEME`; write `light` to `$HOME/.local/share/theme-monitor/theme-change.trigger`; expect Latte `text`, `38;2;76;79;105`.
- `XDG_DATA_HOME moves the trigger file`.
- `WKT_THEME beats the trigger file`.
- `NO_COLOR: no escapes, icons kept`.
- `icons`: U+F46D on the default-branch row, U+F418 on the others, U+F111 on the current row, U+F0338 on a worktree whose folder was deleted (prunable), U+F456 on a locked one.
- `header: hints row`: the `--header` argument contains `open · ^n new · esc quit`.

Code:

- `ui_theme`: `WKT_THEME`, else the trigger file (`${XDG_DATA_HOME:-$HOME/.local/share}`), else `defaults read -g AppleInterfaceStyle` on Darwin only, else light. It fills an associative array `PAL` with `r;g;b` strings for the spec's 14 colours.
- `ui_paint <colour> [bold|dim] <text>` returns plain text when `NO_COLOR` is set.
- `ui_header <hints> [title] [notice]` builds the three rows.
- Widths: columns from `stty size </dev/tty`, else `$COLUMNS`, else 80. List width = columns × 60 / 100 − 3. Cut the path from the left with `…`. Right-align the status icon using `${(m)#…}`.
- Glyph constants: `UI_ICO_BRANCH=$''` and the rest, each with its nerd-font name as a trailing comment.

## Task 6: new-worktree steps

Tests:

- `cmd_new` refactor first: after `wkt new`, nothing visible changes. The existing `new.bats` covers this.
- `ctrl-n: branch, source, then created and printed`. Outside Herdr. Replies:
  1. `0`, `""`, `ctrl-n`, `""`
  2. `1`, `topic` (the branch prompt with `--print-query`)
  3. `0`, `develop` (the source row)

  Then `$LAYOUT/topic` exists, is based on `origin/develop`, and stdout is its path.
- `enter with no match starts new, prefilled`. The list reply is `1`, `fix-login`, `""`. Call 2's args contain `--query` and `fix-login`.
- `bad branch name asks again with a notice`. The branch prompt replies `a..b`, then `ok`. Call 3's `--header` contains `'a..b' is not a valid branch name`.
- `source list: default first, origin branches merged in`. `fzf_input 3` starts with `main` and has `develop` and `feature-x` once each.
- `existing branch skips the source step`. With branch `feature-x` (on origin), only 2 fzf calls; the branch tracks `origin/feature-x`.
- `inside Herdr: label step, then opened with the label`. `herdr_calls` contains `--label Login`, and stdout is empty.
- `inside Herdr: ctrl-o skips Herdr`. No `worktree open` in `herdr_calls`, and the path is printed.
- `esc during new goes back to the list`. Replies: list `ctrl-n` → branch `130` → list `130`. Nothing is created, and the exit is 130.

Code:

- `cmd_new`: at the end, set `typeset -g WKT_PATH=$target_path WKT_HERDR_OPENED=0|1`.
- `ui_ask <title> <prompt> <default> [notice]`: `--print-query --disabled --query <default>`, with stdin from `/dev/null`. Returns 130 on Esc.
- `ui_sources`: `git for-each-ref --format='%(refname:short)' refs/heads refs/remotes/origin`. Strip `origin/`, drop `origin` and `HEAD`, remove duplicates in order, and put the default branch first.
- `ui_new <query>`:
  1. Branch: loop until `git check-ref-format --branch` passes.
  2. Source: skip it if the branch is local, on origin, or already has a worktree.
  3. Label: inside Herdr and not `NO_HERDR`, `--expect ctrl-o --print-query`.
  4. Call `cmd_new` with the collected arguments.
  5. Return 130 to go back to the list.
- `cmd_ui` becomes a loop: list → open, or new. If new returns 130, show the list again. Otherwise print `WKT_PATH` to fd 3, unless `WKT_HERDR_OPENED=1`.

## Risks

- **fzf output order** with `--print-query` and `--expect` is query, then key, then selection. Task 2's tests pin this down. Check it once by hand with real fzf in Task 8.
- **Exit codes:** fzf exits 1 when nothing matches, even with `--print-query`. Treat 1 as success when a query came back.
- **Running inside Herdr's popup or in tmux:** `/dev/tty` sizing can fail there. Fall back to `$COLUMNS`, then 80.
- **`err_exit`:** fzf returning 1 or 130 must not kill the script. Capture with `out=$(…) || st=$?`.
